# fms-m — Review Findings (2026-09-02)

Source: 6-agent parallel review (RTMP core, AMF/byte-IO/crypto, application/media, RTMFP,
server-infra/client, tests/build/docs), weighted toward **modern C++**, **comment prose**,
and **references to bugs that no longer exist**.

Status: `[ ]` open · `[x]` fixed · `[~]` deferred (with reason).
`(v)` = claim verified against source during the review, not just agent-reported.

IDs in this file are independent of the 2026-07 `REVIEW_FINDINGS.md` ID space.

**Out of scope by decision** (reviewers were briefed): `boost::tribool`; the Adobe-compat
crypto floor (RC4/RTMPE, 1024-bit DH group 2, fixed AES-128 key + zero IV, hardcoded
genuine-FMS/FP keys); and the eight 2026-07 items marked `[~]` (H4, M3, M7, M9, M10, M11,
M13, M14). Findings below that touch deferred ground are concrete *additional* sites.

## CRITICAL

- [x] **C1** `ihello_chunk` ctor leaves `m_tag`/`m_epd`/`m_epd_len` indeterminate; dtor
  unconditionally `delete[] m_tag`. A truncated IHello returns false from `deserialize`
  before assigning `m_tag`, and `parser.cpp:133` then deletes the object → `delete[]` on a
  garbage pointer from a single hostile datagram. — `rtmfp/chunk.h:108-111,142-145` (v)
- [x] **C2** AMF3 memory amplification: the `sealed_count` loop copies string-table entries
  **by value** (`traits->m_properties.push_back(read_string(buffer)->value())`). One large
  string + N one-byte back-references multiplies into unbounded allocation within one
  8 MB message. — `amf3.cpp:370` (v)

## HIGH

- [x] **H1** Map iterator dereferenced after the lock is dropped: `lock.unlock();` then
  `m_observer->send_new_stream_notify(i->second)` on an `unordered_map`. A concurrent
  `create()` rehash or `remove()` invalidates `i`. `remove()` at `:28` already shows the
  correct pattern (copy the ptr first). — `netstream_stats_registry.cpp:64-66` (v)
- [x] **H2** Client sink use-after-free: `UnpublishNotify` does `m_sink->close(); delete
  m_sink;` without clearing `m_ns->set_sink()`, so later frames call freed memory. Also
  `av_sink *m_sink;` is the only member with no initializer → `delete` on an indeterminate
  pointer if `UnpublishNotify` precedes `Play.Start`. — `client/ns_event_handler.cpp:21-22`,
  `.h:63` (v)
- [x] **H3** Null `m_app` deref reachable pre-`connect`: `m_app->enqueue_async_message()` is
  unguarded while every other `m_app` use in this layer is guarded. A peer that finishes the
  handshake and sends `eAckSize` bytes without invoking `connect` crosses the notify
  threshold with `m_app` still null. — `basic_rtmp_connection.cpp:36` (v)
- [x] **H4** Expired group member dereferenced: `tmp = i.lock()` is compared to
  `shared_from_this()` but never null-checked before `tmp->peer_id_data()`. —
  `rtmfp/session.cpp:479-483` (v)
- [ ] **H5** Duplicate-fragment check inverted: `if (!f->add_fragment(frag))` where the
  return is `seq_manager::result` and `_eOK == 0`, so the branch fires on **success** and
  never on `_eDuplicate`/`_eProducesGap`. The comment at `flow.h:202` documents the inverse
  of what the enum does. — `rtmfp/session.cpp:154,193` (v)
- [ ] **H6** `aes::encrypt` ignores `EVP_CipherUpdate`'s return after `to.extend()` has
  already handed back uninitialized bytes → uninitialized heap on the wire. `aes::decrypt`
  20 lines earlier checks it and clears. `EVP_CipherInit_ex` (×2) and `EVP_CIPHER_CTX_new`
  unchecked here too. Same class as the fixed H1 (2026-07). — `rtmfp/aes.cpp:17-18,41,52,57` (v)
- [ ] **H7** All three `RAND_bytes` returns ignored — one seeds `m_cookie_secret`, the
  per-process cookie-HMAC key. A failing CSPRNG silently yields a predictable cookie secret,
  defeating the M3 hardening. — `rtmfp/service.cpp:36,52,529` (v)
- [ ] **H8** `EVP_PKEY_CTX_set_dh_pad` return ignored — it is the only thing making the DH
  secret fixed-length. `create_shared_key` then discards the derived length and
  `copy_shared_key` does a bare `memcpy(key, m_shared_key, size)` with callers passing a
  hard-coded 128. Also leaks 128 bytes if called twice. — `evp_dh.cpp:97`,
  `dh.cpp:36-44` (v)
- [ ] **H9** `ctest` runs nothing in a default build: `enable_testing()` appears only inside
  `BUILD_AMF_TESTS` (OFF) and `BUILD_FUZZERS` (OFF), while `add_test` is called under
  `BUILD_CLIENT` (ON) at `:345,:366,:381`. No `CTestTestfile.cmake` is generated at all.
  Separately `b2b_test` — the only end-to-end protocol test — is built and given
  `FMS_SERVER_BIN` but never `add_test`ed. — `CMakeLists.txt:188,273,331-335` (v)
- [ ] **H10** 2026-07 H5 was fixed only on the data path: the three handshake send paths
  call `write(m_serializer->packet(), …)` with no `m_write_in_progress` guard, so a second
  `prepare_packet` can clear/resize the serializer's vectors while the first
  `async_send_to` still holds a raw pointer into them. — `rtmfp/service.cpp:291,476,511` (v)

## MEDIUM

- [ ] **M1** Mixer freed while other clients still feed it: `if (set.size() == 2) … else
  delete m_mixer`. With 3+ clients the *first* departure takes the else branch. Also
  `if (!set.contains(id)) return;` skips the `m_client_to_instance.erase` two lines below.
  — `video_call_application.cpp:186-205` (v)
- [ ] **M2** `vlu_size` infinite loop: `vlu_min <<= 7` reaches 0, so `v >= vlu_min` holds
  forever and `res` (uint8) wraps, for any `v >= 2^63`. `write_vlu` separately caps at
  `size = 22`, silently truncating ≥ 2^29. — `byte_writer.h:90-99` (v)
- [ ] **M3** Client never exits: `m_stopped` is written `false` once, read once, set `true`
  nowhere, so `check_deadline()` re-arms forever holding a `shared_from_this()` and
  `io_context::run()` never returns. — `client/net_client.cpp:19,42`, `.h:81` (v)
- [ ] **M4** Iterator used after a re-entrant callback: `(i->second->m_callback)(...)` then
  `m_result_handlers.erase(i->first)`; that callback reaches `create_stream()` →
  `send_message`, which inserts into the same map. — `client/net_connection.cpp:513-518` (v)
- [ ] **M5** Config-file parse errors escape `parse_cli`: `return check_params();` sits
  outside the `try/catch`, and `check_params` → `parse_config_file` →

- [ ] **M6** Uninitialized stack read as RC4 input: `std::uint8_t d[eHandShakeSize];` then
  `rc4_crypt(m_key_in, eHandShakeSize, d, d)`. Intent is only to advance the keystream, but

- [ ] **M7** Aggregate desync after a failed sub-message: `buffer.skip(h.message_length())`

- [ ] **M8** Decode length silently truncated: the interface declares the payload length as

- [ ] **M9** `rtmfp/dh2` ignores `evp_dh_keygen`/`evp_dh_pub`/`evp_dh_derive` returns; a

- [ ] **M10** Split C0+C1 permanently desyncs an RTMPT session: `handle_data` sets

## LOW — modern C++ (cross-cutting)

  copy double-frees): `rtmp_so_message::event`, `rtmfp::option`, `rtmfp::item`,
  `rtmfp::fragment`, `rtmp_handshaker` (two `EVP_CIPHER_CTX`), `ihello_chunk`. Most want
  `std::vector`/`std::array`, at which point the dtor disappears.
- [ ] **L2** ~18 more unchecked OpenSSL returns beyond H6/H7/H8: `rtmfp/aes.cpp` HMAC ×2,
  `rtmfp/dh2.cpp` `EVP_Digest`, `evp_dh.cpp` `BN_set_word` + 3× `OSSL_PARAM_BLD_push_BN`
